<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| supabase CLI → Edge Function runtime | Deploy com credenciais CLI locais; função passa a receber requisições autenticadas |
| Browser admin → Edge Function | JWT do anon client no header; Edge Function não verifica role do chamador (risco aceito A4) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-14 | Elevation of Privilege | Edge Function deploy com --no-verify-jwt | accept | A flag `--no-verify-jwt` permite chamadas sem JWT da função — mas o cliente Supabase JS sempre envia o JWT do usuário logado automaticamente no header Authorization; a ausência de verificação server-side é risco aceito para piloto (A4) |
| T-13-15 | Spoofing | Smoke test com credenciais reais | accept | Smoke tests usam credenciais de usuários do piloto em ambiente controlado; sem dados sensíveis de produção expostos durante o teste |
| T-13-SC | Tampering | supabase functions deploy | mitigate | Deploy via CLI autenticada (supabase login); verifica que `reset-user-password` aparece em `supabase functions list` antes de considerar N-05 como PASS |
</threat_model>
